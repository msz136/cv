问题（Question）

面试官会问：“world prediction 和 value estimation 为什么会帮助 action imitation？什么时候反而会干扰 policy？多目标梯度如何共享视觉表征，又如何通过 mask/routing 避免互相污染？”

短答案

可直接口述：action imitation 只告诉模型“专家此刻做了什么”，world prediction 迫使视觉表征保留动作后果和环境动态，value estimation 让表征关注哪些状态更接近成功。因此三者共享视觉 encoder 时，world/value 可以给 action head 提供更有规划含义的表示。但它们也可能干扰 policy：如果 world loss 权重过大，表征会偏向像素/未来预测而不是可控动作；如果 value label 噪声大，可能把错误成功先验传给 policy；如果 routing 错，把 world/value 样本也拿去算 action loss，就会污染动作监督。所以项目关键是通过 world/value mask 互斥和 demo/world/value slot routing 控制每类样本只更新对应目标，同时共享底层视觉表示。

Research Framing：多目标 WAM 后训练的研究问题

这个项目不要讲成“跑了 Cosmos Policy 但本地 0 success”。更强的研究叙事是：围绕 action imitation、world prediction、value estimation 三目标是否互补，以及何时互相干扰，做复现、指标验证和失败定位。

1. action / world / value 多目标机制 开放问题是：只做 behavior cloning / action imitation 是否足以学习机器人策略？对应论文背景是 world-action model、video/world prediction 辅助策略学习、value-conditioned representation；本项目直接相关的是 Cosmos Policy / Predict2 RoboCasa 路线。 action imitation 学“专家此刻做什么”，world prediction 学“动作会造成什么后果”，value estimation 学“状态离成功有多近”。三者共享视觉表示时可能互补，但错误权重或噪声 label 会污染 policy。 复现 action/world/value 三目标训练 contract，梳理 world/value mask 互斥、demo/world/value slot routing 和 loss weighting；将机制解释落到样本 routing 和 slot mask，而不是泛泛说多任务。 项目材料曾记录 held-out policy MSE 相对 repeat baseline 下降，但当前缺 split、metric script、prediction/label 与 checkpoint，暂不能把数字写成已验证收益；official-HF eval 也需 raw episode bundle 才能证明本地复现。 MSE 是离线 proxy，不等于 closed-loop success；world/value 是否真正提升在线策略还缺 action-only / action+world / action+value / all 的严格消融。
2. 官方 RoboCasa eval 复现 动机是先验证环境和 eval harness 能跑出可信结果，否则本地训练 0 success 无法归因。对应开放问题是：失败来自模型，还是来自 eval wrapper、stats、action contract、T5/proprio/vision 输入错配？ 如果官方 HF baseline 在同环境成功，而本地 checkpoint 失败，那么问题更可能在本地训练或采样路径，而不是 benchmark 或 wrapper 完全不可用。 部署 nvidia/Cosmos-Policy-RoboCasa-Predict2-2B，对齐 Predict2 + T5 + RoboCasa config / stats / action contract，记录 action_debug、selected rollout 和 trusted success。 项目材料曾记录 official HF checkpoint 的 24 tasks × 5 episodes 结果；当前工作区没有 model revision、raw/trusted summary、episode records 或 videos，因此只能作为待核 provenance 线索。 即使补齐 artifacts，这也只能证明 official checkpoint 的本地 harness reproduction，不是 local WAM 训练结果；在证据补齐前，不口述具体分数。
3. 本地训练失败诊断 研究动机是把 0 success 拆成可验证假设，而不是停在“没跑出来”。开放问题包括 gripper 负向稀疏、high-sigma sampler denoise、conditioning frame 数、checkpoint 保存与国产算力训练稳定性。 0 success 不一定来自数据源错误或 action slot 解码错误；可能是负向 gripper 条件映射在 full training / official sampler distribution 下没有学到，或 checkpoint/DeepSpeed contract 中断训练。 做 gripper bias audit、offline teacher-forced、query probe、eval-state mining、negative-only/sigma aux gate、DeepSpeed no-cycle 修复和 checkpoint 保存诊断。 项目材料描述了 official-baseline、stats/slot roundtrip、fixed-batch、eval-query、gripper、OOM 与 state_dict 的排查链；当前没有对应日志、diff、checkpoint 或 paired rerun，故只能列为候选原因与待取证步骤。 本地训练线不能写成成功率提升，也不能说 root cause 已确认；后续要补可加载 checkpoint、修复前后对照、action-only vs multi-objective 消融和正式 closed-loop eval。

辅助目标为什么可能帮助 Action Imitation

目标学到的信号如何帮助 action可能干扰
Action imitation 专家动作分布 \(p(a_t|o_t,c)\) 直接训练 policy 输出 容易学到短视 repeat 或数据偏置
World prediction 动作后果、未来观测、环境动态 让视觉表征包含“做这个动作后会发生什么” 权重过大时会偏向预测视觉细节，降低动作判别性
Value estimation 状态到成功/回报的可达性 让表征关注任务进展和成功相关特征 value label 噪声会误导 policy

一个简化训练目标可以写为：

\[ \mathcal{L} = \lambda_a m_a \mathcal{L}_{action} + \lambda_w m_w \mathcal{L}_{world} + \lambda_v m_v \mathcal{L}_{value} \]

其中 \(m_a,m_w,m_v\) 是样本级或 slot 级 mask，\(\lambda_a,\lambda_w,\lambda_v\) 是损失权重。关键不是公式本身，而是 mask/routing 决定“哪个样本更新哪个 head”。本项目简历中对应的是 action/world/value 三目标、world/value mask 互斥、demo/world/value slot routing。

Mask / Routing 如何避免互相污染

def wam_training_step(batch, model):
    # batch.type 决定该样本是 demo/action、world prediction 还是 value estimation。
    z = model.visual_encoder(batch.images)

    # 三个 head 共享视觉表征，但 loss 由 routing 控制。
    pred_action = model.action_head(z)
    pred_world = model.world_head(z)
    pred_value = model.value_head(z)

    # mask 保证每类样本只对目标 head 产生梯度。
    action_loss = batch.m_action * mse(pred_action, batch.actions)
    world_loss = batch.m_world * world_objective(pred_world, batch.future)
    value_loss = batch.m_value * mse(pred_value, batch.value)

    # world/value mask 互斥，避免同一 slot 同时承载冲突语义。
    loss = wa * action_loss + ww * world_loss + wv * value_loss
    return loss

面试中可以说：“共享的是视觉 encoder，隔离的是目标 head 和 loss route。”这比“我复现了三目标训练”更能体现算法理解。

6. 高频追问

追问推荐答法防线 / 证据
world prediction 学到的是什么？它学习动作之后环境状态如何变化，包括物体位置、接触状态和任务进展。对 action imitation 来说，它让共享视觉表征更关注“动作会造成什么后果”。不要说它一定提升 policy；要看权重、数据和 mask。
value estimation 和 reward model 有什么区别？value estimation 预测当前状态到成功的可达性或回报，作为辅助表示学习目标；reward model 通常用于给动作或回答打分。这里 value 不是替代 action head，而是帮助表征理解任务进展。不要说 value head 直接控制机器人动作。
为什么 action imitation 会学 repeat baseline？如果数据里相邻动作平滑且任务短，模型可能只学到“重复前一动作”或局部均值，离线 MSE 看起来不差，但遇到接触、转折或恢复状态时会失败。用 first-action-repeat baseline 解释 proxy，不要泛泛说 imitation 有偏差。
policy MSE 为什么是合理 proxy？它可衡量 held-out 动作是否比 repeat baseline 更接近专家，但必须先冻结 split、horizon/dim reduction、metric code 和 checkpoint。当前具体数字缺 raw bundle，不作为已验证结果。proxy 不是在线成功率；无 artifacts 时连 proxy 数字也不报。
MSE 降低为什么不等于成功率提升？闭环成功还取决于误差累积、接触动力学、视觉分布偏移、采样路径和成功判定。离线一帧动作接近专家，不代表 rollout 中每一步都能回到专家状态分布。当前历史 MSE claim 本身也缺 artifacts；先核验 proxy，再讨论 online gap。
三目标共享哪些参数？共享底层视觉/时序表示，让 action、world、value 都能影响对环境和任务进展的编码。Cosmos 更像 slot/mask contract；不要硬说三个独立 head 简单拼接。
哪些 head 是分开的？面试里可以简化说目标输出和 loss route 是分开的：action 更新动作目标，world 更新 future/world 目标，value 更新价值目标。重点是 loss mask 决定梯度去向。若被追实现细节，用本地报告里的 slot/mask 口径防守。
mask 互斥具体防什么？防止同一个 slot 或样本同时承载 world/value/action 冲突语义，避免非动作样本污染 action loss，也避免 value 噪声直接压过动作监督。证据是 loss_mask_smoke 和 routing 检查。
routing 错了会怎样？routing 错会让样本更新错误目标，比如 world 样本被当 action 学，或者 value label 污染动作表征，表现为离线 loss 看似下降但 rollout 行为异常。可举 gripper/slot 诊断作为类比。
world loss 权重大会怎样？模型可能更擅长预测未来视觉或像素细节，但 action 判别性下降。机器人策略不需要完美视频预测，而需要对可控状态和动作后果敏感。不要把 world loss 越大越好。
value label 噪声会怎样？如果 value label 把失败状态误标成接近成功，policy 表征会学到错误任务进展，进而影响动作选择和恢复判断。需要 label 来源和噪声分析，不要默认 value 可靠。
为什么短时序任务更好？短时序任务误差累积少、接触阶段少，world/value 辅助也更容易覆盖完整任务进展。长任务则更容易在早期小偏差后进入 OOD 状态。不要把短任务成功泛化到长 horizon。
pick-and-place 为什么更难？它涉及视觉定位、接触、抓取姿态、夹爪控制和放置位置，任一环节小误差都会累积。相比按钮/开关类任务，对动作精度和恢复能力要求更高。可结合 RoboCasa 失败视频分类。
RoboCasa 和 LIBERO 有什么差别？RoboCasa 偏厨房 manipulation，包含更多接触和场景变化；LIBERO 更规整、便于策略评估对比。两者都可用于机器人策略，但难点分布不同。不要拿一个 benchmark 的结论直接证明另一个。
如何从失败视频判断问题来源？先看视觉目标是否识别错，再看动作方向和幅度，再看夹爪开合和接触点，最后看是否进入无法恢复状态。结合 action debug 能区分视觉、动作尺度和控制执行问题。视频判断要配 action/debug 日志，不能只主观描述。
是否做过在线 rollout？项目材料记录过 official-checkpoint 与 local-checkpoint rollout 线索，但当前工作区没有 model revision、episode summary、视频和 checkpoint load log；面试中应如实说“待取证”，不报具体分数。official checkpoint 不是自己训练模型；项目页自述也不是 raw evidence。
下一步会先调 action loss 还是 world/value？先保证 action contract 和 gripper/action 分布能闭环有效，再逐步加 world/value。原因是 action 主任务不过关时，辅助目标再复杂也可能只是掩盖问题。先主任务，再辅助目标；符合诊断顺序。
这和 UWM 有什么关系？WAM 关注 action/world/value 多目标训练机制，UWM 更关注世界模型策略在 LIBERO 上的 strict eval protocol。两者都涉及世界/动作建模，但一个偏训练目标，一个偏评估协议。不要混用 WAM 的失败诊断去支撑 UWM 指标。
这个项目最大的限制是什么？当前工作区没有 local raw run bundle，因此 official-checkpoint reproduction、local 0-success、MSE proxy 与诊断因果都还不能作为已核验结果。现阶段价值在机制对齐、证据合同和最小诊断设计。主动承认限制，避免被问穿。
你个人贡献在哪里？当前可保守说我围绕公开 recipe 梳理训练评估 contract，并把项目材料中的异常拆成可验证假设；哪些代码亲手改、哪些由上游/工具/协作者完成，仍需用 local diff 与 ownership ledger 逐项确认。不要说“我设计了上游 routing”或“我提升了 RoboCasa 策略成功率”。

追问树与回答分层

问题危险回答可过回答强回答
“world/value 为什么会帮 action？” 多任务训练一般会更好。 它们提供辅助监督。 world 提供动作后果建模，value 提供任务进展信号；二者改善共享视觉表征，但必须通过 mask/routing 控制梯度。
“什么时候会干扰？” 一般不会。 权重不合适会干扰。 world 权重过大、value label 噪声、样本 routing 错误、slot 语义冲突都会污染 action head。
“MSE 降了为什么成功率不一定涨？” 应该会涨。 离线和在线不同。 MSE 只看动作接近专家，在线成功还取决于闭环误差累积、contact dynamics、视觉状态分布偏移和成功判定。

Grill Me：高压追问答复卡

高压追问推荐口述危险边界需要证据
world prediction 为什么会帮助 action imitation？ action imitation 只监督“当前专家做什么”，world prediction 额外要求模型理解动作之后环境会怎么变化。对于机器人任务，这能让共享视觉表征保留可控物体、接触状态和任务进展，而不是只拟合局部动作均值。它帮助 action 的前提是 world 目标和动作相关，而不是只学像素细节。 不要说 world prediction 一定提升 policy；它可能把表征带偏。 action/world/value loss mask、policy MSE、失败视频或 future prediction 样例。
value estimation 为什么会帮助？它和 reward model 有什么不同？ value estimation 给的是状态到成功的可达性或任务进展信号，帮助表征关注哪些视觉状态更接近成功。它不是泛泛的 reward model，也不是替代 action loss；更像一个辅助目标，让共享表示对“当前状态是否值得继续执行”敏感。 不要说 value head 直接决定机器人动作；policy 输出仍由 action 目标约束。 value target 构造、mask 路由、value label 噪声分析。
什么时候 world/value 会反而干扰 policy？ 三类情况最危险：world loss 权重过大，模型偏向预测视觉细节而不是可控动作；value label 噪声大，错误成功先验污染表征；routing 或 mask 错，把 world/value 样本也拿去算 action loss，导致动作监督被非动作样本污染。 不要把多任务训练讲成无条件正收益。 loss 权重、mask smoke、slot routing 检查。
多目标梯度如何共享视觉表征，又如何避免互相污染？ 共享的是底层视觉/时序表示，隔离的是目标 slot、loss mask 和 route。demo/action 样本主要更新 action 目标，world 样本更新 future/world 目标，value 样本更新 value 目标；world/value mask 互斥，避免同一 slot 同时承载冲突语义。面试里我会说：共享 encoder 是为了迁移语义，mask/routing 是为了控制梯度边界。 不要说它们是三个完全独立的 head 后简单相加；Cosmos Policy 更接近 slot/mask contract。 loss_mask_smoke、sample_dict 字段、训练配置。
历史材料里的 MSE 降低为什么不能直接写策略成功率提升？ 第一层问题是当前没有 split、metric code、prediction/label 与 checkpoint，连 proxy 数字都尚未核验；即使补齐，MSE 也只说明 held-out 动作拟合，闭环还受误差累积、接触、状态分布、采样和 success predicate 影响。 不要把 proxy 指标当在线成功率。 held-out 划分、first-action-repeat baseline、online eval 结果。
官方 RoboCasa eval 复现有什么价值？ 逻辑价值是先用 official checkpoint 证明 harness，再诊断 local checkpoint；但当前工作区没有这次 24×5 reproduction 的 raw summary、episodes 或 model revision，所以我只解释验证设计，不把项目页记录的具体分数当已核实结果。 不要报未取证的历史分数；即使核实，official checkpoint 也不是自己训练模型。 eval_summary_officialhf_baseline.json、selected rollout、action_debug。
本地训练 0 success 怎么讲，才不像失败项目？ 我会把它讲成 evidence-gated reproduction 与 failure diagnosis：先把项目材料中的 gripper、normalizer/slot roundtrip、fixed-batch、5-frame conditioning、eval query 和 high-sigma sampler 拆成假设，再为每项规定日志、unit test 与 paired rerun。当前没有 raw bundle，因此不说哪些已排除或已确认。 不要把待核的 0-success 叙事藏掉，也不要把它或其原因包装成已验证性能结论。 gripper diagnostics、query probe、eval-state mining、negative-only aux gate。
沐曦 8 卡 1 epoch 主线为什么值得讲？ 项目材料描述了 MACA/C500 上的 dataloader cycle、CPU memory cgroup OOM、DeepSpeed checkpoint 与 state_dict 断点；在日志、diff、rerun 和可加载 checkpoint 到位前，我只能把它们列为待确认的迁移问题，不能说已经修复并闭环。 不要说完成了 1 epoch final checkpoint；当前没有可加载 final checkpoint。 run_contract、OOM 日志、no-cycle 修复、save1500 失败日志。
