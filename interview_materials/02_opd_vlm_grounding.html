问题（Question）

面试官会追问：“OPD 为什么优于单一 teacher 或单一 SFT？提升到底来自数据分布、teacher 融合，还是格式对齐？”

短答案

可直接口述：我不会把提升单因果地归因给 OPD。更严谨的解释是三层贡献叠加：第一，开源清洗样本提供 box grounding 冷启动，场景标注/合成样本补足长尾语义和空间分布；第二，SFT 主要解决输出格式、基础定位能力和多类型任务统一；第三，OPD 的价值是在线整合多个 teacher 的互补信号，让 box、point、text、bool 四类 grounding 在同一训练分布里联合优化，减少单一 teacher 的偏置。当前指标支持这个机制解释，但如果要严格拆因果，还需要单 teacher、仅 SFT、无场景合成数据等 ablation。

机制拆解：三类收益不要混讲

来源解决的问题对指标的可能贡献面试防线
数据分布 开源清洗样本初始化 box grounding；场景标注/合成 pipeline 扩充长尾语义、空间关系和任务语言。 提升覆盖率、减少无框/错框、改善 held-out Mean IoU。 可以说“数据分布是基础”，不要说“只靠数据就够”。
SFT 格式对齐 让模型学会按统一格式输出 box、point、text、bool，减少格式错误和多任务混淆。 提升 strict format、降低无效输出。 SFT 是冷启动和格式对齐，不是最终主成果。
OPD 多教师融合 不同 teacher 对对象定位、文本判断、布尔判断、point hit 的强弱不同；在线融合避免单 teacher 偏置。 提升综合 raw-holdout，尤其是 Text loose、Box Acc@0.5、Bool acc。 没有 ablation 时，只说“证据支持”，不要说“已证明唯一原因”。

面试中建议用一句话打底：“数据决定覆盖，SFT 决定格式，OPD 决定多任务 teacher 信号如何被联合优化。”

训练目标解释

可以把 OPD 讲成一个多教师、多输出类型的加权监督目标。令 \(T_k\) 表示第 \(k\) 个 teacher，\(z\) 表示输入图像与任务文本，\(y^{(m)}\) 表示第 \(m\) 类输出目标，\(m \in \{box, point, text, bool\}\)。一个简化目标是：

\[ \mathcal{L}_{OPD} = \sum_{m} \sum_{k} \alpha_{m,k}(z) \cdot \ell_m(f_\theta(z), T_k^{(m)}(z)) \]

变量解释：\(\ell_m\) 是对应输出类型的损失或 reward，\(\alpha_{m,k}\) 表示在当前样本和输出类型上 teacher 的权重。实现映射上，报告中只能把它作为机制解释，因为本地简历证据证明了多教师融合和指标结果，但没有完整暴露每个 teacher 的权重函数。面试中可说“OPD 的思想是按任务类型和样本状态整合 teacher，而不是盲目平均所有 teacher”。

def opd_training_step(batch, teachers, student):
    # 1. 输入包括图像、语言指令和目标输出类型：box / point / text / bool。
    z, output_type = batch["input"], batch["output_type"]

    # 2. 多个 teacher 产生候选监督信号。
    teacher_targets = [teacher.predict(z, output_type) for teacher in teachers]

    # 3. 根据样本类型、置信度或规则选择/加权 teacher 信号。
    weights = compute_teacher_weights(z, output_type, teacher_targets)

    # 4. 学生模型在统一格式下学习多类型 grounding 输出。
    pred = student(z)
    loss = weighted_grounding_loss(pred, teacher_targets, weights)
    return loss

4. 2-3 分钟口述稿

这个项目是语义导航 grounding 的数据与训练目标设计。问题不是简单地让模型输出一个框，而是要在机器人场景里统一处理 box、point、text、bool 多种 grounding 输出。我的做法是先用开源清洗样本初始化 box grounding 能力，再用场景标注和合成 pipeline 补足长尾语义和空间分布，最后把这些样本统一到 OPD 在线多教师融合目标里。SFT 的作用主要是格式对齐和冷启动，OPD 的作用是融合不同 teacher 在不同输出类型上的互补信号，避免单一 teacher 的偏置。结果上，13,879 个标注框和 41,637 条样本支撑迭代，held-out Mean IoU 从 0.1319 到 0.3501；相对 Qwen3-VL-8B-Instruct，Text loose 提升 35.4pp、Box Acc@0.5 提升 8.0pp、Bool acc 提升 8.8pp。边界是目前没有把每个收益完全拆成 ablation，所以面试里我会把它表述为机制解释和指标支持，而不是绝对因果证明。

追问树与回答分层

问题危险回答可过回答强回答
“提升到底是谁贡献的？” 主要是 OPD。 数据和 OPD 都有贡献。 拆成数据覆盖、SFT 格式对齐、OPD teacher 融合三部分；当前指标支持组合机制，但需要 ablation 拆因果。
“为什么多 teacher 比单 teacher 好？” 多个 teacher 更强。 不同 teacher 能互补。 不同输出类型的错误分布不同，多 teacher 融合能降低单 teacher 在某类输出上的系统偏置，尤其是 text/bool 与 box 的监督粒度不同。
“合成数据会不会过拟合格式？” 不会，我们数据质量高。 需要 held-out 检查。 这是风险，所以要用真实场景 held-out、格式错误率和不同输出类型指标一起看；不能只看训练 loss。
