A. World Model 基础与范式

L1 P0 VLA-WM-001 · 什么是 world model？它与 policy、environment simulator、reward/value model 分别是什么关系？

面试意图：检查你能否先划清模块职责，再讨论 architecture 或项目收益。

30 秒回答：world model 是给定历史与候选动作、预测未来 observation/state/latent、reward 或 continuation 的条件模型。policy 选动作，真实 environment/simulator 产生 transition，reward 给即时信号，value 估计长期回报；world model 本身不等于规划器。

机制展开（约 2 分钟）：先报概率合同 history + action + task -> future variables。World Models 用 VAE+MDN-RNN 学 latent future，PlaNet 用 latent dynamics 在线规划，Dreamer 从 posterior belief 出发用 prior imagination 训练 actor/critic。一个视频生成器只有在动作合同、horizon、reward/termination 或 decision utility 可验证时才承担 world-model 角色；否则它只是视觉预测器。learned model 也不等于环境本体。

诊断 / 消融：逐项问推理时是否查询 future、由谁选 action、reward/value 是否独立、预测是否进入 controller；用 no-world、auxiliary-world、planning-world 三组合同对照。

项目挂钩：讲 WAM/UWM 时先说明 world head 是训练辅助还是 rollout-time query；上游结构和项目页数字都不是个人已验证结果。

追问树：没有像素 decoder 还能叫 world model 吗？reward model 算 world model 吗？world model 与 simulator 的关键差别是什么？

危险答案：把 world model 等同于“能生成视频”，或说它天然包含 policy、value 和 controller。

来源：[1][2][17][18][19][20]　练习状态：unseen

L2 P0 VLA-WM-002 · world model 应建模 observation、state、latent、reward、termination 中哪些变量？

面试意图：判断你是否会按用途设计 I/O，而不是机械堆齐所有 head。

30 秒回答：没有固定全家桶。感知侧输入 observation；高维或部分可观测任务常用 latent/belief；planning/RL 通常需要 reward 与 continuation。privileged simulator state 只可作监督或诊断，不能泄漏到部署输入；每个字段还要冻结时序、mask、horizon 和终止语义。

机制展开（约 2 分钟）：POMDP 中真实 state 转移、observation 由 state 产生；模型可用 encoder 与 recurrent belief 近似 state。decoder 保留可重建信息，reward head 给一步信号，continuation 决定 imagined return 是否跨过 terminal。纯 auxiliary model 可只学 latent future；queryable simulator 则必须输出 planner 真正需要的 future/reward/termination。privileged simulator state 只能在明确 flag 下作 target/probe。

诊断 / 消融：做字段级 ablation：去 decoder、reward、continuation 或 privileged target；分别报告 representation probe、open-loop error、return 与 closed-loop success。

项目挂钩：核对 UWM/WAM 数据中 camera、proprio、action、future/value slot 与 mask；缺 local schema 时不猜哪些字段真正训练。

追问树：termination 与 truncation 为什么不能合并？latent 是否必须能解码图像？privileged state 怎样避免泄漏？

危险答案：说 world model 必须同时预测像素、state、reward、value 和 done，或把 simulator state 当部署输入。

来源：[1][2][17][20]　练习状态：unseen

L2 P1 VLA-WM-003 · deterministic dynamics 与 probabilistic dynamics 各自能表达什么不确定性？

面试意图：检查你能否区分点预测、多未来、数据噪声与模型知识不足。

30 秒回答：deterministic dynamics 给点估计，稳定但会平均多未来；probabilistic dynamics 输出分布，可表达 aleatoric 多模态。epistemic 来自覆盖不足，通常需 ensemble 或 posterior/disagreement；单个随机模型不自动代表 epistemic uncertainty。

机制展开（约 2 分钟）：deterministic 常以 MSE 拟合条件均值，适合低噪声 state 和短 horizon；Gaussian/mixture/categorical latent/diffusion 可表示多未来，但要冻结采样 seed、temperature 与 likelihood/denoise 合同。ensemble 的成员差异可作为 epistemic proxy，但若成员训练高度相关或未校准，disagreement 也不等于真实风险。选择取决于是否存在遮挡、接触、多解和 planning 风险。

诊断 / 消融：比较 deterministic、single stochastic、ensemble 的 NLL/coverage、horizon error、calibration 与 risk-sensitive planning success，不能只看 sample 多样性。

项目挂钩：UWM/video diffusion 的采样随机性最多先证明多样性；没有 ensemble/calibration 和环境对照，不能称本地 epistemic risk 已解决。

追问树：为什么 MSE 会模糊多未来？aleatoric 能否靠更多数据消除？ensemble disagreement 什么时候失真？

危险答案：说 deterministic 模型没有任何不确定性，或把 diffusion 的 sampling noise 直接称为 epistemic uncertainty。

来源：[1][2][17][19][20]　练习状态：unseen

L3 P0 VLA-WM-004 · latent world model 的 encoder、transition、decoder、reward 与 continuation head 如何连接？

面试意图：考查你能否把 RSSM 的 filtering、imagination、loss 与 actor/critic 数据流连起来。

30 秒回答：encoder 编码 observation；posterior 用当前观测更新 latent belief，prior 仅靠历史 latent 和 action 想象未来。decoder、reward、continuation head 从 belief 预测观测、回报与是否继续；训练对齐 prior/posterior，规划时不能读取未来观测。

机制展开（约 2 分钟）：DreamerV3 风格 RSSM 由 deterministic state h 与 stochastic state z 构成：observe 做 posterior filtering，imagine 做 action-conditioned prior rollout，dyn/rep KL 用不同 stop-gradient 方向，free-nats 防止过度压 KL。world heads 分别有 target、scale、mask；actor/critic 从 replay posterior start 出发在 prior 中 rollout reward/continue。danijar repo 是 reimplementation，不是论文官方代码。

诊断 / 消融：检查 posterior-vs-prior gap、KL/free-nats、各 head loss、posterior collapse；做 future-observation leakage test 和 prior-only horizon rollout。

项目挂钩：项目若声称使用 RSSM，必须给 local module/config/checkpoint/tensor trace；不能用 Dreamer upstream code 代替本人实现证据。

追问树：posterior/prior 为什么分开？continuation 怎样影响 return？decoder 去掉会怎样？PlaNet overshooting 能否直接归给 DreamerV3？

危险答案：让 imagination 读取未来 observation，或称 danijar/dreamerv3 为 Google/DeepMind 官方代码。

来源：[1][2][17][20][21]　练习状态：unseen

L2 P0 VLA-WM-005 · one-step prediction 好为什么不代表 multi-step rollout 可靠？

面试意图：检查你是否理解 teacher-forced 分布与自回归状态漂移。

30 秒回答：one-step 每次站在真实 history 上；open-loop 从第二步开始吃自己的预测。局部误差会被 dynamics sensitivity 反复传播，rollout 还会进入训练外 state；背景占优、action ignoring 或 continuation/contact 漏建模都可能让平均 MSE 很低但长时轨迹失真。

机制展开（约 2 分钟）：把第 j 步局部误差记为 e_j、局部放大因子记为 L，h-step error 会累积近似加权项；当 L>1 或 state OOD 时增长更快。pixel MSE 可能被静态背景主导，latent/reward loss 也只证明对应 target fit。正确评估要画 teacher-forced 与 autoregressive error_by_horizon，固定 action/seed/reset，并配 task-object pose、contact、action sensitivity 和 continuation error。

诊断 / 消融：做 horizon 1/4/8/... sweep、真实-history vs predicted-history 对照、action swap、对象区域/状态指标与 terminal audit。

项目挂钩：UWM/WAM 离线 future MSE 下降只能说相应 split/horizon 拟合改善，不能直接升级为 LIBERO success。

追问树：为什么背景会掩盖错误？L 是什么直觉量？open-loop 好是否就等于 closed-loop 好？

危险答案：只报一个平均 one-step MSE，就声称 world model 可做长时 planning。

来源：[1][2][17][19][20]　练习状态：unseen

L3 P1 VLA-WM-006 · teacher forcing、open-loop rollout 与 scheduled sampling 的分布差异是什么？

面试意图：判断你能否从训练输入来源解释 exposure bias，而不是只背术语。

30 秒回答：teacher forcing 始终喂真实前一步，训练稳定但模型没见过自己的错误状态；open-loop 始终回灌预测，用来暴露 compounding；scheduled sampling 按 schedule 混用真实/预测输入，试图缩小 gap，但会引入新的训练分布和目标不一致，不能替代 open/closed-loop 评测。

机制展开（约 2 分钟）：scheduled sampling 可用 Bernoulli mask 决定每步取 ground truth 还是 model prediction，必须记录 teacher probability、stop-gradient、padding 与 episode boundary。它可能让模型适应有限预测噪声，也可能破坏序列目标的一致性；若 action、termination 或 schema 本身错，混入预测输入只会适应错误。评测要在同 start/action/seed 下分别跑 teacher-forced、autoregressive 和 closed loop。

诊断 / 消融：对 schedule、prediction detach 与 rollout horizon 做 sweep；分报 one-step、open-loop、closed-loop，不把三种 MSE 合并。

项目挂钩：若项目只保存 teacher-forced future loss，就不能宣称训练已覆盖 rollout-state distribution；需要 config 和真实 open-loop trace。

追问树：scheduled sampling 为什么有 bias？预测输入是否 detach？closed loop 与 open loop 的 observation 来源有何不同？

危险答案：说 scheduled sampling 一定消除 exposure bias，或把 teacher-forced validation 当 autoregressive rollout。

来源：[1][2][17][19]　练习状态：unseen

L3 P1 VLA-WM-007 · aleatoric 与 epistemic uncertainty 如何区分，分别怎样影响 planning？

面试意图：考查你能否把 uncertainty 分类落实为校准、拒答和风险敏感决策。

30 秒回答：aleatoric 是同一条件下环境本身有多种结果，更多同分布数据也未必消失；epistemic 是模型没覆盖或不知道，补数据/ensemble 可能降低。planning 中前者需要对多 outcome 做期望或约束，后者应触发 pessimism、abstention、fallback 或补采数据；两者都必须校准。

机制展开（约 2 分钟）：单模型分布内部 variance 可近似 aleatoric，不同 ensemble 成员预测均值的 variance 可近似 epistemic，但这是估计框架。风险目标可写成 predicted return 减 uncertainty penalty；beta 决定保守度。必须验证 coverage、reliability、OOD detection 与 success/constraint trace。高 disagreement 可能来自成员不稳定，低 disagreement 也可能是共同过拟合，不能把数值直接当安全保证。

诊断 / 消融：做 in-distribution/OOD calibration、ensemble size、risk beta、abstention threshold 与 fallback 对照，同时报告成功率和 constraint violation。

项目挂钩：当前 UWM/WAM 没有 local ensemble/calibration artifact；安全说法是会这样设计，而不是已解决不确定性。

追问树：diffusion 多样性属于哪类？更多数据对两类 uncertainty 的作用？pessimism 过强会怎样？

危险答案：把 sample variance 当完整 epistemic uncertainty，或声称 uncertainty penalty 天然保证安全。

来源：[1][2][17][19][20]　练习状态：unseen

L2 P0 VLA-WM-008 · video generation model 何时可以叫 actionable world model，何时只是视觉预测器？

面试意图：检查你能否从“画面逼真”推进到 action intervention 和 decision utility。

30 秒回答：至少过四关：候选动作以真实 axis/unit/time 进入模型；固定起点换动作时 future 有差异；差异方向与 simulator/真实 intervention 对齐；这些 future 能改善候选筛选或失败发现。只有视频质量、FVD/PSNR 或文本动作条件，最多说明视觉预测，不证明 actionable dynamics。

机制展开（约 2 分钟）：先做 action swap、magnitude、gripper、noop、order tests，复用 observation 与 sampler seed；再从 cloned state 执行动作，比 object pose、joint/contact delta。sensitivity 只证明模型有反应，alignment 才说明方向对；短时 alignment 也不证明长 horizon。decision utility 还要比较 proxy rank、planning selector 与 same-protocol closed-loop，同时记录 latency 和 failure cases。

诊断 / 消融：action-free、shuffled-action、correct-action 三组；pixel/feature/pose/contact 与 closed-loop 指标分层报告。

项目挂钩：UWM/Cosmos 是上游 action-conditioned 例子；没有 local checkpoint 和 intervention trace，不能说本人已验证物理正确。

追问树：action sensitivity 高为什么仍可能错？文本条件算 action 吗？FVD 能证明什么？

危险答案：说“生成视频很真实，所以模型理解动作和物理”。

来源：[1][2][3][4][17]　练习状态：unseen

L2 P1 VLA-WM-009 · world model 作为 policy auxiliary representation 与作为可查询 simulator 有何区别？

面试意图：判断你是否会区分训练辅助目标与 test-time model-based planning。

30 秒回答：auxiliary 训练时加 future/world loss，推理可不用 world head，收益靠公平的 action-only vs +world 消融。queryable simulator 推理时 rollout 候选的 future/reward/termination 后选择，更依赖 OOD action 覆盖、校准与 latency。

机制展开（约 2 分钟）：auxiliary 目标可改善共享表示，也可能因 gradient conflict、shortcut 或额外数据混杂而负迁移；必须记录 routing、loss mask、weight 与 gradient scope。queryable 模式要记录 proposal N、world/value checkpoint、rollout/denoise steps、selector、replan 和 cost。训练时出现 world loss 不等于 model-based control；planning uplift 也不能只归因 world head，除非 value、N 与 protocol 有消融。

诊断 / 消融：action-only、+world、planning-world 三臂；再分 world/value/N/selector 与 latency，比较同 init closed loop。

项目挂钩：WAM 项目叙述先说明现有 run 是 multi-task pretraining、direct policy 还是 planning；缺 runtime trace 时不混写。

追问树：无 decoder 的 latent auxiliary 算 world model 吗？为什么 planning 更怕 OOD action？额外视频数据怎样控制？

危险答案：看到 future loss 就说系统在推理时用 world model 规划。

来源：[1][2][4][17]　练习状态：unseen

L3 P0 VLA-WM-010 · model bias 与 rollout compounding error 如何导致“想象中很好、真实执行失败”？

面试意图：考查你能否解释 planner exploitation，并设计候选级别的归因实验。

30 秒回答：transition 偏差随 horizon 累积并把 rollout 推入 OOD；planner 又会选择 world/value 最乐观的候选，N 越大越易命中幻觉、物理漏洞或 value 高估。再叠加 normalizer、controller、contact 与 recovery mismatch，imagined return 高不等于真实成功。

机制展开（约 2 分钟）：把候选固定后保存 imagined future、value、uncertainty，并从 cloned env state 执行 selected 与 random/median control。按 horizon 比 transition delta、constraint violation 和 rank；做 N、selector、horizon sweep。如果 selected candidate 的 model score 升而真实 return 降，是 optimizer's curse 信号。再查 action transform/controller tracking、terminal/contact 和首次偏离后的 recovery，避免把接口失败全归给 backbone。

诊断 / 消融：random/median/top selector、N/horizon、oracle-state/value、model bypass 与 controller replay；记录 first divergence。

项目挂钩：WAM/UWM 的 0-success 或高 proxy 低 success 只能先按这条链诊断；无 raw episodes 时不声称已定位 root cause。

追问树：为什么 N 增大可能更差？怎样区分 transition bias 与 value bias？receding horizon 能完全解决吗？

危险答案：认为更多候选和更长 rollout 必然更好，或只凭最后失败帧归因 world-model backbone。

来源：[1][2][4][16][17][19][20]　练习状态：unseen

E. World Model 评估与失败归因

L3 P0 VLA-WM-039 · UWM / LIBERO 的 checkpoint、normalizer、init、warmup、horizon 与 rollout 数怎样构成 strict protocol？

面试意图：判断你能否把“严格评测”落实成可重放合同，而不是只对齐 task 名和 rollout 数。

30 秒回答：strict protocol 是模型、初态和执行判定的完整合同。我会冻结 task/init、warmup、观测预处理、action/normalizer、H/K、controller/Hz、horizon、success predicate、随机性、trial 聚合，以及 checkpoint/code/runtime；任何字段不一致都先视为不同协议。

机制展开（约 2 分钟）：把协议写成 \(\mathcal P=(S,I,W,O,A,K,C,H,Y,R,N,M)\)，每个 run 保存 checkpoint/config/stats SHA，每个 episode 保存 task、init、seed、success、step、异常与 trace hash。比较 A/B 时复用同一 pair_id=(task, init, seed)，从 immutable episode records 聚合结果。UWM 论文 Table II OOD init、官方仓库 random-reset runner 与本地 fixed-pruned-init claim 分属三个 setting，不能因任务和 50 rollouts 相同就混名。

诊断 / 消融：先做 protocol manifest diff；若任一字段未知就阻断分数比较。补齐后只改一个因素并做 same-init paired rerun，同时保留 invalid episode 与预先声明的清洗规则。

项目挂钩：现阶段可讲“我识别并拆开了三种协议”；74.4%/92.8% 仍缺 checkpoint、stats、init、chunk/horizon 和逐 episode 记录，只能标为 claim-only。

追问树：为什么 H 与 K 都要冻结？warmup 是否计入 horizon？macro/micro average 怎样选？paired episode 为什么能减少 init 难度噪声？

危险答案：说“用了相同 LIBERO 任务、50 次 rollout，所以就是 strict reproduction”。

来源：[1][3][6][7][8][9][14]　练习状态：unseen

L2 P0 VLA-WM-040 · world model open-loop prediction metric 与 closed-loop policy success 怎样建立但不夸大关联？

面试意图：检查你能否分清 proxy 的证据层级，并设计它与真实行为指标的验证关系。

30 秒回答：分层报告 component、one-step、open-loop、WM proxy、sim success 和 real success。低层变好只证明对应 target/horizon；要在多个 policy variant 上检验 proxy 与同协议闭环的排名和不确定性，不能用单点替代真实评测。

机制展开（约 2 分钟）：one-step error 在 rollout 中会被局部 dynamics sensitivity 与 OOD state 逐步放大，因此至少画 error_by_horizon 并标明 teacher-forced 还是 autoregressive。proxy 验证需要预先定义多个真实不同的 checkpoint，在同一 task distribution 上得到 proxy \(q_j\) 与 closed-loop success \(p_j\)，检查 rank consistency、seed/CI 和 bad cases。即使排序稳定，也只支持已测 policy/task/scorer 版本，不能声称数值等价或替代 sim/real。

诊断 / 消融：做 horizon sweep、action-conditioned counterfactual 和多 checkpoint rank test；分别报告 action/future/value component metric、proxy、sim 与 real，不用 total loss 掩盖断点。

项目挂钩：WorldGym 可作为 deployment 前筛选框架；UWM/WAM 的离线 MSE 或生成质量不能自动升级为 LIBERO success，更不能写成 Sim2Real。

追问树：为什么单个 checkpoint 不能谈相关性？Spearman 高说明什么、不说明什么？image MSE 更低但 success 更差有哪些原因？

危险答案：说“open-loop 指标越好，closed-loop success 必然越高”，或用 simulator success 证明真实机器人泛化。

来源：[1][2][3][4][6][12][13]　练习状态：unseen

L3 P0 VLA-WM-041 · offline future/action/value loss 下降但 online success 不变时，如何设计消融？

面试意图：考查你是否能把多目标收益拆成可归因实验，而不是从 total loss 直接推断策略提升。

30 秒回答：做 action-only、+world、+value、all 的 2×2 消融，四臂共享数据、初始化、预算和协议，并在相同 init 上 paired eval。分报 component loss、action sensitivity、value calibration、闭环结果与开销，定位 offline→online 断点及 interaction。

机制展开（约 2 分钟）：对结果 \(Y_{w,v}\) 分解 world 主效应、value 主效应和 \(world\times value\) interaction；A11 更好不代表两个 auxiliary 单独都有效。若 +world 额外使用更多视频，需再控制 data amount。action MSE 降但 success 不变先查 norm/axis 与 rollout-state shift；value MSE 降但 best-of-N 变差查 OOD overestimate；A10 好、A11 差则查 gradient conflict、label 与 weight。每个 cell 要多 train seed，并在同一 episode pair 上报告 online uncertainty。

诊断 / 消融：补 gradient cosine/weight sweep、expert-state 对 rollout-state error、random/median/top selector 与 planning-N sweep；同时 diff run manifest，避免 checkpoint/protocol 漂移冒充目标冲突。

项目挂钩：WAM 的 MSE、84/118 和 0-success 目前缺 local checkpoint 与 raw episodes；只能用它们说明要做哪组消融，不能据此声称 auxiliary 已带来收益。

追问树：为什么 all 更好不能归因两个 auxiliary？如何控制额外数据量？value optimizer's curse 是什么？四臂预算怎样对齐？

危险答案：只比较 action-only 与 all，看到 total loss 下降就说 world/value 对 policy 都有帮助。

L3 P1 VLA-WM-042 · 如何检测 hallucination、physical inconsistency、action insensitivity 与 causal inconsistency？

面试意图：判断你能否从“视频看起来合理”推进到可干预、可度量的 world-model 一致性测试。

30 秒回答：hallucination 是生成无依据状态；physical inconsistency 是违反几何或接触约束；action insensitivity 是换动作而 future 几乎不变；causal inconsistency 是会变但方向错误。固定起点和噪声做反事实，再从 cloned simulator state 执行动作并对齐环境变化方向。

机制展开（约 2 分钟）：action swap、magnitude sweep、gripper 正反、noop 和时间置换先测模型是否使用 action；再从同一 simulator state 执行 baseline/candidate action，比较预测与环境中的 object pose、joint/contact delta，而不是只比像素。按 horizon 统计 error 与 penetration、悬浮、关节越界、对象守恒等 violation。高 sensitivity 也可能是噪声放大，只有与环境 intervention 方向一致才支持局部 causal alignment，仍不证明长时真实物理。

诊断 / 消融：每对反事实复用 observation、start state 与 sampler seed；按 axis、magnitude、gripper、order 和 horizon 分桶，并区分视频/VLM proxy 与 simulator-state ground truth。

项目挂钩：可为 UWM/Cosmos world head设计这套 test suite；没有 local checkpoint 和执行 trace 前，不能声称已验证物理正确或真实机器人因果性。

追问树：action sensitivity 高为什么仍可能错？只有视频时怎样标记物理 judge？为什么要 clone state？如何检测 gripper sign 反转？

危险答案：用 PSNR、FVD 或“视频看起来逼真”直接证明模型理解动作和物理。

来源：[1][2][3][4][6][7][10]　练习状态：unseen

L2 P0 VLA-WM-043 · 失败轨迹怎样按 perception、dynamics、contact、planning、controller 和 recovery 分层回写数据？

面试意图：检查你是否会定位第一处可观测断点，并把失败路由到正确的数据、代码、目标或评测 owner。

30 秒回答：0-success 时别猜 backbone；按 protocol/checkpoint→observation→action/controller→dynamics/contact→planning/value→recovery 找断点。接口 bug 修代码与单测，覆盖缺口补数据，world/contact/value/recovery 各回写自己的目标。

机制展开（约 2 分钟）：每个 episode 对齐 raw/model observation、normalized/raw/env action、queue/controller state、predicted/real pose、contact、candidate/value 和 success trace。先排 protocol、checkpoint 与 normalizer，再找最早时间戳：flip/时序错、axis/gripper 错、stale chunk、跟踪误差、接触丢失、value 选错或恢复失败。只路由证据确认的 family；action contract 错误不能当新标签训练，recovery 缺口应采 first-deviation 后的 corrective trajectory。

诊断 / 消融：做 manifest diff、image/timestamp replay、action round-trip、expert action replay、K/latency sweep、cloned-state intervention、contact trace、N/selector/calibration sweep与 predicate audit。

项目挂钩：WAM 的 0-success 或 UWM 单条失败先当待分类 episode；没有完整 trace 时只描述诊断计划，不把它包装成本人已修复的模型问题。

追问树：为什么先查 protocol？first divergence 与最终 failure label 有何区别？哪些失败该补数据、哪些只该修 harness？

危险答案：看到最后抓取失败就归因 perception/backbone，或把所有失败轨迹无差别加入训练集。

L3 P0 VLA-WM-044 · 如何从 paper/repo/checkpoint/eval harness 核对 world model 的真实训练和 rollout 合同？

面试意图：考查你能否建立完整证据链，并把上游方法、运行结果与个人贡献分开。

30 秒回答：把 claim 拆成方法、配置、指标、协议和 ownership，再核对 paper→repo→checkpoint/assets→runtime→local diff。每层注明支持与不支持什么；revision、artifact 或 protocol 有缺口就降为 claim-only，并按最弱证据原子表述。

机制展开（约 2 分钟）：paper 证明方法与论文 setting，不证明当前 default；repo 证明某 commit 的路径，不证明论文 run；checkpoint/stats 证明资产存在，不证明能加载或成功；runtime 需要 exact controller/protocol 与 episode records；ownership 还需 local diff、design note 和命令/日志。ledger 含 claim、source、supports、does-not-support、protocol、artifact SHA、ownership、verdict，并区分 primary、official-code、local-evidence、inference、unverified。

诊断 / 消融：逐原子寻找 evidence chain；对缺口提出最小补件，如 env patch、stats SHA、load log、paired episode JSONL 或 local diff。只比较协议相同的 run，并对数字、因果和个人贡献分别给 verdict。

项目挂钩：74.4%/92.8%、WAM MSE/84/118 与 upstream UWM/Cosmos 结构当前不能串成“我的严格复现/创新”；安全说法是已完成 source audit，raw artifacts 仍待补。

追问树：repo default 能否证明论文实验？checkpoint 能加载是否证明分数？团队成果怎样标个人 ownership？哪类证据可把 claim-only 升级？

危险答案：把论文数字、官方 baseline、本地 smoke test 和个人贡献合成一条强叙事。
