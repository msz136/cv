VOL 06 PER-009 Source Freeze：Grounding Matching、Negative 与 Loss Reduction

状态：source_frozen / VLA-PER-009 / primary_official_checked / local_ce_top1_kl_boundary / knowledge_synced / card_synced / WARN 冻结日期：2026-07-20 证据截止：2026-07-20 本切片只冻结显式grounding detector与本地OPD生成式训练的objective、matching、negative和reduction合同；不生成knowledge/card，不展开PER-010 metric/parser、PER-011 pseudo-label/noise或PER-015 controller gate。

问题（Question）

Grounding模型训练时，Hungarian matching究竟匹配什么？matching cost和最终training loss为什么不能混用？未匹配query、非目标token、padding、负图像和hard negative分别是什么？focal、L1、GIoU、auxiliary loss如何reduction？本地OPD的assistant-token CE、routed top-1 CE与teacher-KL能否口述成Grounding DINO式detector loss？

本页冻结的可审计链为：

prediction/target schema + positive token map
  -> pairwise matching cost matrix
  -> one-to-one assignment
  -> matched positive + unmatched/token negative targets
  -> classification/localization loss components
  -> token/object/sample/batch/distributed reduction
  -> auxiliary/encoder branches and logged diagnostics
  -> project-specific objective boundary

1. 结论先行

  1. matching cost不是training loss：Hungarian阶段只决定query与GT的离散一对一assignment；最终梯度来自assignment后的classification、L1、GIoU及可选auxiliary/encoder losses。两阶段即使使用同名组件，也可能有不同权重与计算形式。
  2. Grounding DINO的类别轴是text-token轴：冻结的Transformers 4.57.1实现将class label映射为token positions；matching class cost聚合目标phrase的token focal-style cost，最终classification对有效text positions做binary focal loss。
  3. negative至少分四层：未匹配query的全零token target、匹配query中的非目标token、dataset级negative image/prompt、以及挖掘或采样出的hard negative不是同一概念。当前source只直接冻结前两类；dataset/hard-negative recipe仍未验证。
  4. padding不是negative：Transformers实现用text_mask排除padding；本地生成式路径用labels=-100排除prompt/padding。把masked位置当negative会改变分母与梯度。
  5. reduction顺序是objective的一部分：GroundingDINO focal/L1/GIoU按跨worker平均GT box数归一化；本地top-1先对每个样本的有效token求mean，再route加权，再对batch求mean；online KL也先token mean、再sample weight、再batch mean。交换顺序并不等价。
  6. focal loss处理easy-negative dominance，不自动完成negative mining：它以alpha平衡正负，以gamma下调well-classified examples；它不能替代dataset-level negative coverage、label correctness或calibration。
  7. 版本权重不能靠记忆：Grounding DINO v5正文叙述与附录Table 8在classification matching/final loss权重上不一致；Transformers 4.57.1默认值与Table 8一致。因此必须保存paper revision、config与runtime loss dictionary，不能口述一个无revision的“官方权重”。
  8. 本地OPD不是显式detector criterion：point_sft.py是assistant-token supervision；train_opd_top1_vl.py是object/region teacher top-1 token CE；train_opd_online_vl.py是full-vocabulary teacher distribution KL。所读路径没有query set、Hungarian matcher、unmatched-query negatives、L1/GIoU head或detector auxiliary loss。
  9. loss下降不等于grounding或robot成功：2500行本地metrics可复算first/last窗口的optimization信号，但没有在本切片绑定同protocol holdout、checkpoint、parser输出或robot episode，不能据此推出quality uplift。

4. 显式Grounding Detector的训练schema

Transformers 4.57.1实现所需最小tensor合同：

对象Shape / 语义关键约束
logits[B,Q,L] query×text-token logitsL是token positions，不是固定class数
pred_boxes[B,Q,4] normalized cxcywhmatching与loss前格式固定，GIoU时转corners
labels[b].class_labels[M_b]索引当前sample的label map
labels[b].boxes[M_b,4] normalized cxcywhM_b可随sample变化
label_maps[b][C_b,L]class/phrase→token positions；phrase内token归一化用于matching
text_mask[B,Q,L] bool只允许有效attention positions进入classification loss
indices[b](query_idx,target_idx)Hungarian一对一assignment，长度为min(Q,M_b)
num_boxesscalar跨worker平均GT数并clamp_min(1)

原始GroundingDINO repo的create_positive_map_from_span从character spans构造[num_boxes,256] map并对phrase token归一化；Transformers 4.57.1则按delimiter/special-token groups构造label_maps。两种map construction不能在无golden test时视为完全等价。

5. Hungarian Matching：离散assignment合同

令第\(i\)个query为\(q_i\)，第\(j\)个GT为\(t_j\)，pairwise cost可抽象为：

\[ C_{ij}=\lambda_{\mathrm{cls}}C^{\mathrm{token}}_{ij} +\lambda_{1}\lVert \hat b_i-b_j\rVert_1 +\lambda_{G}\bigl(-\operatorname{GIoU}(\hat b_i,b_j)\bigr), \qquad \hat\sigma=\arg\min_{\sigma}\sum_j C_{\sigma(j),j}. \]

变量解释：\(\hat b_i,b_j\)是predicted/target normalized boxes；\(C^{\mathrm{token}}\)是query对目标phrase tokens聚合的classification cost；\(\lambda_{\mathrm{cls}},\lambda_1,\lambda_G\)是matching阶段权重；\(\hat\sigma\)是一对一assignment。

直觉：先决定“哪一个query负责哪一个GT”，再计算梯度；assignment本身是离散选择。实现映射：Transformers的GroundingDinoHungarianMatcher先算focal-style positive/negative token cost、torch.cdist(...,p=1)与negative GIoU，再调用SciPy linear_sum_assignment。证据边界：该式概括paper与version-pinned implementation bridge，不证明本地OPD存在此matcher。

matching的三个关键边界：

  1. cost矩阵不是loss tensor，不能把matching cost曲线当train loss；
  2. unmatched queries不会获得box regression target，但仍可能进入classification negative loss；
  3. 每个auxiliary decoder output会重新matching，不保证所有层复用final assignment。

6. Token Classification、Negative与Focal Loss

6.1 Grounding DINO token target

Transformers bridge先创建全零target_classes_onehot，只在matched query位置写入目标phrase token map。随后用text_mask选择有效text positions：

matched query + target phrase tokens -> positive target 1
matched query + other valid tokens  -> negative target 0
unmatched query + all valid tokens  -> negative target 0
padding/out-of-attention positions  -> masked out, not negative

这说明“background/no-object”在该实现中不是DETR categorical classifier的单独最后一类，而是所有有效token均为0的binary target。dataset-level negative image、wrong phrase采样或hard-negative mining没有被这段实现自动定义。

6.2 Focal loss

对binary target，令\(p_t\)是正确标签的模型概率，focal loss为：

\[ \operatorname{FL}(p_t)=-\alpha_t(1-p_t)^\gamma\log p_t. \]

变量解释：\(\alpha_t\)平衡positive/negative类别；\(\gamma\)控制easy-example down-weighting；GroundingDINO/HF冻结实现使用alpha=0.25、gamma=2作为相应路径默认值。

直觉：当\(p_t\to1\)时，easy example的贡献按\((1-p_t)^\gamma\)快速衰减，但hard example仍保留较大梯度。实现映射：先binary_cross_entropy_with_logits(reduction="none")，再乘modulating factor和alpha，最后按冻结reduction归一化。证据边界：focal loss只能证明loss重加权，不能证明negative dataset覆盖或probability calibration。

确定性probe（negative的\(\alpha_t=0.75,\gamma=2\)）：p_t=0.99时loss约7.54e-7，p_t=0.5时约0.129965，hard/easy约1.72e5倍。该probe只验证公式，不是训练效果。

7. Box L1与GIoU Loss

assignment之后，仅matched pairs进入box supervision：

\[ \mathcal L_{\mathrm{box}} =\frac{1}{N_{\mathrm{gt}}} \sum_{(i,j)\in\hat\sigma} \left[ \lambda_1\lVert\hat b_i-b_j\rVert_1 +\lambda_G\bigl(1-\operatorname{GIoU}(\hat b_i,b_j)\bigr) \right]. \]

变量解释：\(N_{\mathrm{gt}}\)是跨worker平均后、至少为1的GT box数；\(\hat\sigma\)是matching结果；L1作用于normalized cxcywh；GIoU前转为corner format。

直觉：L1直接约束坐标，GIoU补充overlap/relative geometry，尤其避免普通IoU在不重叠时完全无区分。实现映射：HF base loss用l1_loss(reduction="none").sum()/num_boxes与(1-diag(generalized_box_iou)).sum()/num_boxes。证据边界：training GIoU loss不是PER-010中的evaluation IoU protocol，二者不能共享分母或threshold。

8. Reduction、Distributed Normalization与Auxiliary Loss

8.1 Classification numerator与GT denominator

HF GroundingDINO focal bridge对text_mask后的所有valid query-token logits求sum，再除以num_boxes。因此：

  • unmatched-query negatives进入numerator；
  • padding不进入numerator；
  • denominator是GT box count，不是valid token数、query数或batch size；
  • negative数量随prompt length与Q变化时，loss scale也可能变化。

8.2 Distributed denominator

base loss先统计local sum(len(class_labels))，若distributed/Accelerate已初始化则跨rank reduce，再除world size并clamp(min=1)。这近似每worker平均GT数，而不是全局token mean。复现必须保存world size、per-rank targets、gradient accumulation与empty-target batch行为。

8.3 Weighted total与auxiliary branches

Transformers 4.57.1的version-specific总loss为：

\[ \mathcal L =2\mathcal L_{\mathrm{ce}} +\lambda_{\mathrm{bbox}}\mathcal L_{1} +\lambda_{\mathrm{giou}}\mathcal L_{\mathrm{giou}} +\sum_{l\in\mathrm{aux}}\mathcal L^{(l)} +\mathcal L_{\mathrm{enc}}, \]

其中默认bbox_loss_coefficient=5、giou_loss_coefficient=2，classification final coefficient在该loss bridge写死为2；auxiliary decoder层与two-stage encoder复制对应weight dictionary。变量解释：\(\mathcal L^{(l)}\)是intermediate decoder loss；\(\mathcal L_{\mathrm{enc}}\)仅在two-stage路径出现。

直觉：深监督让中间层也直接收到matching/class/box梯度；实现映射：auxiliary_loss和two_stage来自config，且每个aux output重新matching。证据边界：这些是Transformers 4.57.1实现值，不是所有GroundingDINO checkpoint的实际runtime config。

cardinality_error在base criterion中只作logging，不在GroundingDINO weight_dict中，因此不反向传播。不要把loss dictionary中的每个key都当成优化目标。

10. 三个确定性Probe

10.1 Hungarian assignment

对cost matrix[[0.2,1.3],[1.2,0.1]]，SciPy assignment为q0→t0,q1→t1，总cost0.3；alternate总cost2.5。该probe证明全局一对一最小化，不证明任何模型分数正确。

10.2 Focal easy/hard negative

前述p_t=.99/.5得到约7.54e-7/0.129965。该probe证明easy negative被强烈下调，不证明hard-negative mining或calibration。

10.3 Local route reduction

若一个both样本的object/region token-mean CE为2/4，weights为.5/.5，sample loss为3；第二个object样本loss为8，batch mean为5.5。先拼所有token再求global mean通常不会得到同一结果，说明reduction order必须进入manifest。

11. 本地OPD三条Objective Lineage

11.1 Assistant-token SFT

point_sft.py对full conversation与prompt-only conversation分别tokenize，用prompt_len把labels[:prompt_len]设为-100；collator也以-100补齐labels。它证明prompt/padding不计入model loss，assistant output token被监督。

但该文件把实际CE交给loaded model/Transformers Trainer；仅凭本地wrapper不能冻结具体model class内部的shift/reduction。更重要的是SafeTrainer会在encode/filter失败、non-finite loss或training exception时返回zero-loss step并记录bad-batch log。若只看aggregate train loss而不统计zero-loss/dummy/retry事件，会低估数据与数值问题。

11.2 Routed object/region top-1 CE

train_opd_top1_vl.py构造obj_top1_labels/reg_top1_labels，只在原assistant supervised positions写teacher token ID，其余为-100。对每个样本分别求valid-token mean CE：

\[ L_b=w_{b,o}\,\operatorname{mean}_{t\in T_b}\operatorname{CE}(z_{b,t},y^o_{b,t}) +w_{b,r}\,\operatorname{mean}_{t\in T_b}\operatorname{CE}(z_{b,t},y^r_{b,t}), \qquad L=\operatorname{mean}_{b}L_b. \]

变量解释：\(T_b\)是sample \(b\)未被-100屏蔽的response positions；\(w_o,w_r\)在single route为1/0或0/1，both为.5/.5；\(z\)是student logits，\(y^o,y^r\)是teacher top-1 token IDs。

直觉：每个样本先等权平均自身token，再按route混合，最后样本等权。实现映射：F.cross_entropy(...,reduction="mean")返回sample CE，sample_loss.mean()形成batch loss。证据边界：这不是full-distribution distillation，也没有detector query/box matching。

11.3 Online full-vocabulary KL

train_opd_online_vl.py先由student或teacher生成response，只取全部或prefix (T_b) positions，teacher/student在同一generated sequence上输出full-vocabulary logits：

\[ q_{b,t}=\operatorname{softmax}(z^T_{b,t}+\beta\,\operatorname{stopgrad}(z^S_{b,t})), \qquad L_b=\frac{1}{|T_b|}\sum_{t\in T_b}\operatorname{KL}(q_{b,t}\Vert p^S_{b,t}), \qquad L=\operatorname{mean}_b(w_bL_b). \]

变量解释：\(z^T,z^S\)是teacher/student logits；\(\beta\)是veto schedule系数，0时target就是teacher distribution；\(p^S\)是student softmax；\(T_b\)由response/prefix长度决定；\(w_b\)是sample route weight。

直觉：它监督整个vocabulary distribution而非单个top-1 token；实现映射：代码先逐token求KL，再以token_mask.sum(...).clamp_min(1)做sample mean，最后(sample_loss*weights).mean()。route必须在microbatch内一致，ZeRO-3预载teacher时各rank也必须同route。证据边界：KL下降不证明teacher正确、parser输出改善或robot成功，teacher noise属于PER-011。
