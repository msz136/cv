问题（Question）

1. 结论先行

  1. 7/7 primary PDFs byte-identical：重新下载的版本、bytes与SHA全部命中source freeze，合计96页；DAgger aggregate、Scheduled Sampling previous-input mismatch、R2R teacher/student forcing、VLN-CE 0.75^n/5,000/4 epochs、DD-PPO同步去中心化与preemption、PPO ratio/clip、多epoch minibatch、GAE的\(\gamma\lambda\) advantage均可直接定位。
  2. 10/10代表official files byte-identical：VLN-CE 3个、Habitat-Lab 5个、R2R-EnvDrop 1个、Matterport R2R 1个文件全部命中source freeze SHA。VLN-CE code确实执行p ** data_it、expert/policy action mix、LMDB append和oracle-action inflection weighting；Habitat code确实保存action log-prob、计算GAE、PPO ratio/clip、value/entropy与grad statistics。
  3. R2R语境中的student forcing可以称online DAgger，但不能无条件泛化：论文p7明确写“equivalent to an online version of DAgger / always sampling”，前提是target始终从agent当前pose到goal的shortest path重新计算。knowledge/card把general case继续要求current-state oracle label是正确收紧，不与论文冲突。
  4. Scheduled Sampling与DAgger仍须分开：前者直接支持true/generated previous token curriculum；它不提供navigation oracle、immutable aggregate或no-regret身份。把ε=0叫always sampling是paper-exact，把任意always-sampling流程叫canonical DAgger则不成立。
  5. termination/truncation分离是本仓库的工程合同，不是pinned Habitat路径的code-exact事实：固定commit 0fb6f43 的ppo_trainer.py读取单一dones并生成not_done_masks，rollout_storage.py只消费masks；该路径没有显式terminated/truncated字段。知识页说“真正terminal切bootstrap、time-limit truncation通常保留bootstrap”是合理目标，但必须标为engineering requirement，不能说该官方代码已经实现。
  6. PPO完整loss是实现相关的：PPO论文直接支持ratio、clipped surrogate和多epoch minibatch；pinned Habitat实现还包含clipped value、entropy、aux loss、可选VER importance coefficients与adaptive entropy。知识页的-Lclip + value - entropy + aux是教学综合，不是该commit逐项完全展开式。
  7. 10/10 probes独立复算通过；它们只验证identity、mask、schedule、GAE、clip和bootstrap反例，不是训练稳定性、论文benchmark或个人项目结果。
  8. 五项目边界再次成立：8个local-direct files重新哈希命中；定向关键词审查只发现UWM的separate rollout eval、OPD teacher rollout和Harness reward spec邻接事实，没有local navigation DAgger collector、visited-state oracle aggregate、fresh PPO behavior log-prob/value/return或matched result。ignored/third-party代码仍不能计入候选人ownership。

本页 verdict 为PASS WITH WARNING：public mechanism与source→knowledge→card对齐通过；pinned Habitat terminated/truncated差异、local runtime、ownership与真实口述仍为warning/pending。

4. BC、Forcing 与 Scheduled Sampling 复核

BC教学目标写为：

$$ \mathcal L_{\mathrm{BC}}( heta)= -\frac{\sum_{b,t}m_{b,t}w_{b,t}\log\pi_\theta(a^*_{b,t}\mid o^E_{b,t},h^E_{b,t},c_b)} {\sum_{b,t}m_{b,t}w_{b,t}+\varepsilon}. $$

变量与映射：\(a^*\)是expert action，\(m\)是valid-action mask，\(w\)可表达inflection/sample weighting；R2R official code直接支持cross-entropy target，VLN-CE dataset支持oracle action与inflection weight。此式是对离散action trainer的安全教学综合，不是R2R论文逐字公式。empty denominator必须在公式外先gate；\(\varepsilon\)不能把空batch变成有效更新。

Scheduled Sampling的核心门为：

$$ a^{\mathrm{in}}_{t-1}= \begin{cases} a^*_{t-1},&z_t<\epsilon_i,\\ \hat a_{t-1},&z_t\ge\epsilon_i. \end{cases} $$

变量与映射：\(\epsilon_i\)控制true/generated previous input比例；paper直接支持从fully guided到mostly generated的curriculum。它没有定义navigation shortest-path oracle、round dataset或cross-round aggregation，因此knowledge/card说“Scheduled Sampling不自动等于DAgger”通过。

R2R的特殊点是target \(a_t^*\)始终根据agent当前pose重算。论文因此把student forcing称为online DAgger / always sampling。安全口述应说：“在R2R这个current-pose shortest-path oracle语境下等价；离开该语境必须重新检查oracle relabel和aggregation。”

5. DAgger Identity 与 VLN-CE 映射

$$ \pi_i=\beta_i\pi^*+(1-\beta_i)\hat\pi_i, \qquad D\leftarrow D\cup\{(s,\pi^*(s)):s\sim d_{\pi_i}\}. $$

变量与映射：\(\pi^*\)为expert，\(\hat\pi_i\)为learner，\(d_{\pi_i}\)为实际visited-state distribution。DAgger Algorithm 3.1直接包含mixture、visited state expert action、dataset aggregate与retrain；VLN-CE code把p ** data_it映射到\(\beta_i\)，用torch.where(rand < beta, expert, policy)推进环境，并将trajectory追加到LMDB。

VLN-CE的10×5,000是nominal config规模；paper还写6–10次collection取决于model/convergence。知识页把50,000标为nominal并要求扣除invalid/duplicate/early stop是正确边界，不能把配置乘法当实际有效trajectory denominator。

6. GAE、PPO 与 termination/truncation 差异

GAE的paper-exact主体为：

$$ \delta_t^V=r_t+\gamma V(s_{t+1})-V(s_t), \qquad \hat A_t^{\mathrm{GAE}(\gamma,\lambda)}= \sum_{l=0}^{\infty}(\gamma\lambda)^l\delta_{t+l}^V. $$

变量与映射：\(\delta_t^V\)是TD residual，\(\lambda\)控制多步bias/variance；Habitat storage用reverse recursion和masks[step+1]实现有限rollout版本。GAE paper讨论terminal absorbing state，但没有现代Gymnasium式terminated/truncated双字段。

PPO paper-exact主体为：

$$ r_t(\theta)=\frac{\pi_\theta(a_t\mid s_t)}{\pi_{\theta_{old}}(a_t\mid s_t)}, \qquad L^{\mathrm{CLIP}}=\mathbb E_t \left[\min\left(r_t\hat A_t, \operatorname{clip}(r_t,1-\epsilon,1+\epsilon)\hat A_t\right)\right]. $$

变量与映射：old log-prob必须与采样action的behavior policy对齐；Habitat code以exp(new_logp-buffer_logp)求ratio，再计算clipped action loss、value loss、entropy、aux和grad statistics。knowledge页的total objective是教学层综合；pinned code还含可选VER importance coefficients、clipped value与adaptive entropy，不能把简式说成该commit逐行等价。

6.1 新确认的 pinned-code warning

ppo_trainer.py只接收env返回的dones，再构造：

# Fixed Habitat-Lab path: one done flag becomes the bootstrap mask.
not_done_masks = torch.tensor([[not done] for done in dones])

# Rollout storage uses the same mask in TD and GAE recursion.
delta = reward + gamma * next_value * next_mask - value
gae = delta + gamma * tau * gae * next_mask

代码注释与结论：该路径没有显式terminated与truncated字段，因此不能证明time-limit truncation被正确bootstrap。PER-018中“true terminal切bootstrap、time-limit truncation通常保留bootstrap”保留为engineering contract / failure gate；若项目采用这个pinned path，必须另查env wrapper是否在进入dones前处理time-limit信息。

7. DD-PPO 与分布式边界

DD-PPO paper直接支持distributed、decentralized、synchronous、no-stale与straggler preemption。pinned code把DDP wrapper/跨worker mean-variance放在ddppo.py，PPO update放在父类，preemption orchestration位于trainer而不是这个短mix-in文件。配置的sync_frac=.6和total_num_steps=2.5e9是public recipe；不能由“本地多GPU”反推完成论文规模。

工程上仍应记录每worker collected steps、preemption、episode termination与global denominator；这是可复现性要求，不是DD-PPO论文保证每个本地系统自动拥有的artifact。
