问题（Question）

面试官会问：“连续控制动作为什么可以被离散语言 token 表示？这会不会损失精度？horizon 和 action chunk 如何影响闭环控制？LIBERO 结果能代表真实吗？”

短答案

可直接口述：这个项目的关键不是把连续动作“硬塞进文本”，而是把 VLA 的动作建模问题重写成多模态序列预测：输入是图像、状态和任务语言，输出是一个未来 action window。离散 token 表示会带来量化误差，但它也让动作预测可以复用 VLM 的自回归训练、chat template 和 LoRA 微调能力。精度损失主要由动作量化粒度、归一化、horizon 和 controller 执行频率决定。闭环上，模型每次预测一段 action chunk，controller 只执行前若干步，然后重新观测、重新规划。LIBERO 的优势是协议规整、可比性强；边界是它没有完全覆盖真实机器人里的视觉扰动、控制延迟、物理接触和任务组合复杂度。

连续动作为什么能离散化

动作 token 化不是说连续控制本质上是语言，而是把一个连续向量序列编码成模型可生成的离散符号，再在执行前解码回连续动作。令动作维度为 \(d\)，horizon 为 \(H\)，一个 action window 是：

\[ A_{t:t+H-1} = [a_t, a_{t+1}, \ldots, a_{t+H-1}], \quad a_t \in \mathbb{R}^{d} \]

在本项目口径中，DROID 侧使用 horizon=15、dim=72，因此一个训练样本的动作目标可以理解为 \(15 \times 72\) 的连续矩阵。离散 token 化可以抽象为：

\[ q_{i,j} = Q(\mathrm{norm}(a_{i,j})), \quad token = \mathrm{serialize}(q_{1:H,1:d}) \]

其中 \(Q\) 是量化函数，\(\mathrm{norm}\) 是动作归一化，\(\mathrm{serialize}\) 是把量化后的动作矩阵写成 assistant 侧离散动作 token 的序列。实现映射上，对应简历中的“连续 action window 编码为 assistant 侧离散动作 token，统一 DROID horizon=15/dim=72 与 MindCube VLM QA 的数据格式”。

优点风险面试回答
复用 VLM 自回归建模、LoRA、chat template、统一 VLA/VLM co-train 量化误差、长序列误差累积、动作维度相关性被文本序列打散 承认 token 化有误差，但它换来了训练统一性；误差通过 normalization、chunk 执行和闭环 replanning 缓解。

Action Window、Observation Normalization 与 Controller 的闭环

Observation image / proprio / task language
        |
        v
Qwen3-VL + LoRA policy predicts action token sequence
        |
        v
decode tokens -> normalized action window (H=15, dim=72)
        |
        v
denormalize / slice / map to controller action space
        |
        v
execute first K actions, then re-observe and replan

闭环控制里最关键的是 H 和 K 的关系。\(H\) 是模型一次预测的未来动作长度，\(K\) 是实际执行多少步后重新规划：

\[ \pi_\theta(o_t, s_t, c) \rightarrow \hat{A}_{t:t+H-1}, \quad env.step(\hat{a}_t), \ldots, env.step(\hat{a}_{t+K-1}) \]

如果 \(H\) 太短，模型难以表达跨阶段动作意图；如果 \(H\) 太长，后半段动作更容易因为新观测变化而过时。\(K\) 越小，闭环更稳但推理成本更高；\(K\) 越大，执行更流畅但更依赖 open-loop 预测。面试中要讲出这个 trade-off，而不是只报 horizon 数字。

def libero_rollout(env, policy, task, replan_steps):
    # 1. 读取当前图像、机器人状态和任务语言。
    obs = env.reset(task)
    done = False
    while not done:
        # 2. 对 observation/state 做与训练一致的归一化和格式化。
        model_input = build_vla_input(obs, task)

        # 3. 模型输出 assistant 侧动作 token，再解码成未来 action window。
        action_tokens = policy.generate(model_input)
        action_window = decode_and_denormalize(action_tokens)

        # 4. 只执行前 K 步，随后重新观察并规划。
        for action in action_window[:replan_steps]:
            obs, reward, done, info = env.step(action)
            if done or info.get("success"):
                break
    return info

LIBERO Benchmark 的边界

LIBERO 能说明什么不能说明什么面试防线
在规整仿真任务、固定协议和公开 baseline 下，策略能否完成标准 manipulation 指令。 真实机器人视觉扰动、相机偏移、控制延迟、摩擦/接触误差、任务组合泛化。 说“公开可比 benchmark 上超过 baseline”，不要说“真实机器人泛化已解决”。

5. 2-3 分钟口述稿

OpenPiVLA 这个项目我会把它定义成 VLA 动作建模改造，而不是普通复现。我在 OpenPI 框架上接入 Qwen3-VL-2B + LoRA，把连续 action window 表示成 assistant 侧离散动作 token，并统一 DROID horizon=15/dim=72 和 MindCube VLM QA 的数据格式。这样 VLA 的核心问题从“单独训练一个连续动作头”变成“图像、语言、状态到动作 token 序列的多模态预测”。这里的难点是离散化会带来量化误差，所以必须通过动作归一化、action chunk、controller 反归一化和闭环 replanning 保持可执行性。评估上，我按公开 LIBERO 四套件口径得到 goal/object/spatial/libero_10 = 99.0%/99.5%/98.0%/93.0%，平均 97.4%，高于官方 OpenPI pi05_libero baseline 96.85%。边界是 LIBERO 是规整仿真 benchmark，不能代表真实机器人里的全部扰动和延迟，但它能说明在公开协议下这套动作表示和训练策略是有效的。

问题危险回答可过回答强回答
“离散 token 不会损失连续控制精度吗？” 不会，模型能学会。 会有误差，但结果还不错。 承认量化误差，解释 normalization、chunk decode、闭环 replanning 如何降低误差累积，并说明 benchmark 边界。
“这是不是只是换了个 backbone？” 我接了 Qwen3-VL。 还改了动作格式。 强调训练目标和 I/O contract 变化：图像/语言/状态输入统一，连续 action window 被序列化成 assistant 动作 token，支持 VLA/VLM/co-train。
“LIBERO 高分能说明真实吗？” 说明策略很好。 说明仿真任务效果好。 LIBERO 说明公开仿真协议下可比有效；真实机器人还要补视觉扰动、延迟、控制频率、组合任务和安全验证。
